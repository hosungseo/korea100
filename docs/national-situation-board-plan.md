# 국정상황판 기획(안) — 국무총리의 부처 업무 모니터링

> 2026-08-29 2판. 목적을 "국무총리 입장에서 각 부처 업무 모니터링"으로 확정하고
> 1판(사업 포트폴리오 중심)을 부처 축 중심으로 재구성했다. 수치는 전부 이날
> korea100 워룸 4사업(광주 반도체·5극3특·북극항로·대구경북통합신공항) 라이브 데이터 실측.

## 0. 결론

**가능하다. 축만 바꾸면 된다.** 관문 그래프의 모든 관문에는 결정주체(actorRoles.decision)가
붙어 있으므로, 같은 데이터를 "사업별"이 아니라 **"부처별"로 접으면** 총리의 부처 모니터링
화면이 나온다. 이 접기는 이미 광주 사업에서 한 번 검증됐다 — 주체별 종합상황판
(/warroom/board/, 23주체·인계 72건)이 정확히 이 시점 전환이었고, 이번 기획은 그것을
**전 사업 교차로 확장**하는 것이다.

### 총리가 부처에 대해 실제로 묻는 것 — 그리고 오늘 데이터의 답

| 총리의 질문 | 데이터의 답 (실측 예시) |
| --- | --- |
| ① 이 부처가 지금 할 수 있는데 쥐고 있는 것은? | 해양수산부 **5건** (북극항로 특별법 시행·거점항만 개발 등) |
| ② 이 부처가 지연되면 몇 개가 서나? | 행정안전부·산업통상부 **최대 22개**, 국방부 13개 |
| ③ 부처 간 공이 어디서 멈춰 있나? | 인계 뷰 — 광주 보드에서 72건 검증, 교차 확장 대상 |
| ④ 이 부처 소관에서 오늘 무슨 신호가? | 루프 신호의 부처 필터 (수집은 현재 광주만) |

### 부처별 실측 (4사업 135관문, 2026-08-29)

| 부처 | 담당 관문 | 완료 | 진행 | **착수가능** | **최대 레버리지** | 걸린 사업 |
| --- | --- | --- | --- | --- | --- | --- |
| 국토교통부 | 14 | 1 | 6 | 2 | 5 | 3개 |
| 국회 | 13 | 5 | 4 | 2 | 1 | 3개 |
| 해양수산부 | 13 | 0 | 1 | **5** | 11 | 1개 |
| 국방부 | 8 | 1 | 0 | 1 | **13** | 2개 |
| 지방시대위 | 6 | 1 | 2 | 1 | 1 | 1개 |
| 행정안전부 | 5 | 0 | 2 | 0 | **22** | 2개 |
| 산업통상부 | 5 | 1 | 2 | 1 | **22** | 2개 |
| 기획예산처 | 5 | 2 | 3 | 0 | 0 | 1개 |
| 기후에너지환경부 | 3 | 0 | 0 | 1 | 8 | 2개 |
| (이하 교육부·총리국무회의·고용부·복지부·국가유산청·금융위·농식품부·해경청 등) | | | | | | |

읽는 법 — 이 표 한 장이 국무회의 자료가 된다:
- **해양수산부**: 착수가능 5건. "선행조건이 다 풀렸는데 아직 개시 전인 것이 5건"이라는
  뜻이므로 총리가 "해수부, 이 5건 언제 시작하나"를 관문 ID로 물을 수 있다.
- **행정안전부·산업통상부**: 레버리지 22. 이 부처의 관문 하나가 지연되면 하류 22개가
  선다. 관문 수는 적어도 **국정 전체에 대한 지렛대가 가장 크다.**
- **국방부**: 광주·대구경북 두 군공항 사업의 실시계획 승인권을 쥐고 있어 레버리지 13.
- **국회**: 13관문. 부처가 아니지만 총리가 의정 협조를 요청할 대상이 무엇인지 그대로 나온다.

### 미특정 61건 — 정직성의 대가이며, 숨기지 않고 표시한다

관문 135개 중 61개는 결정주체가 "정부", "산업단지 지정권자", "이전부지선정위원회" 같은
역할명이라 특정 부처로 접히지 않는다. 워룸 정직성 규칙("역할명을 부처 실명으로 치환하지
않는다 — 지정 경로 확정 전까지")의 의도된 결과다. 화면에서는 **'미특정' 버킷을 별도로
노출**한다. 이 버킷 자체가 정보다: "누가 결정하는지부터 정해야 하는 관문이 61개"라는
보고가 되기 때문이다.

## 1. 화면 설계

### L0 — 부처 그리드 (홈, 신규)

부처 카드 19+α장. 카드 한 장:

```
┌──────────────────────────────────────────┐
│ 해양수산부                     3개 사업   │
│ 담당 13 · 완료 0 · 진행 1                │
│ ▶ 지금 쥐고 있는 것 5건                  │  ← frontier & 담당. 클릭=목록
│ ⚡ 최대 레버리지 11 (N08 기본계획 심의)   │  ← 지연 시 하류 정지 수
│ 📡 오늘 신호 2 · 최근 검증 08-29         │
└──────────────────────────────────────────┘
```

- 정렬 기본값은 **'쥐고 있는 것' 수 → 레버리지** 순. 관문 수 순이 아니다(아래 §3 오독 방지).
- 진행률 막대 금지, 4카운트 표기(기존 정직성 규칙).
- 마지막 줄에 '미특정 61' 카드를 같은 급으로 배치.

### L1 — 부처 상세 (신규)

한 부처를 열면:
1. **쥐고 있는 것** — 착수가능 & 담당 관문 목록. 각 행: 사업·관문·기다린 일수·레버리지.
2. **이 부처를 기다리는 곳** — 이 부처의 미완료 관문에 hard 의존이 걸린 하류 관문들
   (어느 부처가 기다리는지 포함 → 부처 간 갈등·협조 지점이 드러남).
3. **인계 대기** — 상류 부처가 완료했고 공이 이 부처로 넘어온 관문
   (광주 보드의 인계 모델을 교차 사업으로 확장).
4. **입법 의존** — 이 부처 소관 관문 중 국회·시행령에 걸린 것.
5. **신호 피드** — 루프 신호 중 이 부처 관문에 매핑된 것(보도됨·주시 필요 표기 유지).
6. 각 관문 행 → 해당 사업 지도 딥링크(`?p=<id>` 기존 규약) → 절차 원자·조문(기존).

### L2 — 크로스컷 (1판에서 유지, 부처 렌즈 추가)

- **결정 대기열**(최고위 22건): 부처 필터 추가.
- **공유 의존 매트릭스**(30종): 행에 소관 부처 병기 — "도로·철도 SOC(국토부)가 4사업
  전부에 걸림"이 부처 책임으로 읽히게.
- **입법 파이프라인**(국회 13관문 + 입법예고 시행령): 소관 부처 열 추가.
- 사업 포트폴리오 홈: 1판의 B화면을 보조 렌즈로 유지(부처→사업, 사업→부처 양방향).

## 2. 데이터 — 새로 만들 것

기존 파이프라인(제도 원장 647종 → 관문 그래프 → `--all` 생성기 → 정적 파일 → Pages)은
그대로. 추가분:

1. **`ministry-board.json` 집계** — `--all` 마지막에 부처별 접기(이 문서 실측 코드가 원형).
   결정주체 문자열→부처 정규화 사전은 기존 `MINISTRY_CANON`을 전 부처로 확장
   (부분 문자열 오매칭 함정은 mega-tier에서 이미 학습: "재정부서"→'정부' 류 금지, 구체 토큰만).
2. **인계 교차 확장** — 광주 보드의 handoffs 모델을 4사업으로. produces→requires 토큰이
   이미 있으므로 "상류 완료 & 하류 미개시 & 부처가 다름"을 계산하면 된다.
3. **신호 수집 다사업화** — 사업별 키워드 프로파일(현재 광주만). 부처 필터는 관문 매핑을
   경유하므로 별도 작업 없음.
4. **기다린 일수** — frontier 진입 시각을 기록해야 "며칠째 쥐고 있나"가 나온다.
   루프가 일 1회 도니 스냅샷 diff로 저장(신규, 소규모).

## 3. 운영 원칙 — 부처 모니터링이기에 더 무거워지는 것

1판의 정직성 규칙(신호≠확정, 역할명 실명 치환 금지, 빈 막대 금지, 수기 수치 금지,
시행예정 법령까지 확인)에 더해:

- **관문 수·레버리지는 성과 지표가 아니다.** 부처 서열화·평가에 쓰이는 순간 데이터가
  오염된다(부처가 관문 등재 자체를 다투게 됨). 화면 문구를 "업무량"이 아니라
  "지금 공이 어디 있는가"로 일관되게 유지한다.
- **커버리지 한계 명시.** 이 상황판이 보여주는 것은 부처의 전체 업무가 아니라
  **등재된 사업에 걸린 관문**뿐이다. 현재 4사업 기준 해수부 13관문이지 해수부 업무가
  13개인 게 아니다. 사업을 국정과제로 확장할수록 부처 그림이 완성된다 — 즉 부처
  모니터링의 완성도는 사업 온보딩 수에 비례한다(사업 1개 반나절, 실측).
- **부처 정정 창구.** 상황판 표시가 부처 입장과 다를 때의 정정 요청 경로(제도
  '요청하기' 패턴 재사용)를 처음부터 연다.

## 4. 못 하는 것 (1판과 동일, 재확인)

예산 집행률 없음(dBrain 연계 전) · 정무·여론 없음 · 실시간 아님(일 1회+사람 검증) ·
공식 보고 채널 아님(공개 신호 기반). 부처의 **일상 행정**(민원·집행·인사)은 범위 밖이고,
**국가 핵심사업에서 각 부처가 맡은 관문**의 모니터링이다.

## 6. 리스크 (부처 축 고유)

- **서열화 오독**: 표가 부처 평가표로 읽히는 순간 협조가 끊긴다. → §3 원칙 + 화면 문구 통제.
- **미특정 61건의 방치**: '미특정' 버킷이 크면 부처 화면의 신뢰가 떨어진다. → 버킷을
  "결정주체 확정 필요 목록"이라는 업무 큐로 운영(5극3특 감사에서 26건을 채운 절차 재사용).
- **단일 사업 부처의 왜곡**: 해수부는 사실상 북극항로 1개 사업 수치다. 카드에 "N개 사업
  기준" 병기로 표본 크기를 항상 노출.
