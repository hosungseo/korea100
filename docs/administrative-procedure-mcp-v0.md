# 행정절차 MCP v0.2

## 제품 정의

행정절차 MCP는 **결재나 업무 단계가 끝난 뒤 해야 할 다음 행정행동을 설명하는 인터페이스**다. 법령 원문을 검색하는 서비스와 달리, 법령을 업무 단계·행위자·문서·기한·분기·인계 관계로 재구성한 Korea100 데이터를 사용한다.

v0.2는 실제 온나라 연계가 아니라 그 전에 검증할 수 있는 연결 계약이다. 비식별 이벤트를 받아 제도와 단계를 식별하고, 사람이 확인할 인계 패킷까지 만든다. 실제 결재·접수·발송 권한은 갖지 않는다.

## 전자결재 연계 개념

```text
전자결재·업무시스템의 비식별 이벤트
  -> 이벤트 메타데이터 안전성 검사
  -> 제도와 현재 단계의 보수적 식별
  -> 법령 대조 신선도·분기 조건 확인
  -> 사람 검토용 다음 행동 패킷 생성
  -> 담당자 확인
  -> 별도 실행 시스템에서 후속 업무 수행
```

MCP는 패킷 생성까지만 맡는다. 결재 상신, 문서 발송, 민원 처리, 연구비 집행처럼 상태를 바꾸는 행위는 별도 실행 게이트웨이의 권한과 감사로그를 거쳐야 한다.

## v0.2 결정

- 전송: 로컬 통합에 단순한 stdio
- SDK: 2026년 7월 현재 안정판인 MCP TypeScript SDK v1.29
- 데이터 범위: R2 대표 제도 3개
- 법령 연결: 저장된 법제처 DRF 대조 결과와 `law.go.kr` 공식 원문 직접 링크
- 법령 신선도: 마지막 현행 원문 대조 후 기본 30일, 만료 시 경로 선택 중단
- 이벤트: 결재완료·반려·보완요청·문서접수·수동확인의 비식별 메타데이터만 허용
- 개인정보: 주민등록번호·전화번호·이메일 형태를 거부하고 이벤트 원문은 저장하지 않음
- 감사 연결: 이벤트 지문, 결정 지문, 법령 인용 지문을 응답에 포함
- 쓰기 기능: 없음

## 이벤트 최소 계약

| 필드 | 의미 | 원칙 |
|---|---|---|
| `metadata_only` | 본문·첨부를 제외했다는 확인 | 반드시 `true` |
| `source_system` | 시스템 식별자 | 개인 이름이나 연락처 금지 |
| `event_type` | 결재완료·반려 등 이벤트 유형 | 허용 목록만 사용 |
| `procedure_hint` | 제도 slug 또는 정확한 제도명 | 권장 |
| `step_hint` | 단계 ID 또는 정확한 단계명 | 권장 |
| `document_title` | 비식별 문서 유형·서식명 | 선택 |
| `actor` | 개인이 아닌 기관·역할명 | 선택 |
| `condition` | 담당자가 확인한 분기 조건 | 모르면 생략 |

`procedure_hint`와 `step_hint`가 정확히 일치하거나, 정확한 제도와 고유 문서 유형이 함께 확인될 때만 자동 매핑한다. 그 외에는 후보만 제시한다.

## 사람 검토용 패킷

패킷에는 현재 단계 완료 증빙, 선택된 인계 주체와 문서, 다음 단계의 기한·완료 조건, 법제처 공식 원문, 미확인 질문, 이벤트·결정·법령 지문이 들어간다. 패킷 상태와 관계없이 다음 값은 고정한다.

```json
{
  "execution_allowed": false,
  "human_confirmation_required": true
}
```

## 응답 원칙

1. 현재 단계는 제도 slug와 단계 ID 또는 단계명으로 명시한다.
2. 다음 단계가 하나면 해당 전이를 반환하되 사람 확인을 요구한다.
3. 분기가 둘 이상이면 조건이 확인되기 전까지 어느 경로도 선택하지 않는다.
4. 조건 문구가 여러 분기에 걸치면 모호한 것으로 처리한다.
5. 다음 단계와 함께 인계 주체, 문서, 시작 조건, 완료 기준, 기한, 근거조문과 공식 링크를 반환한다.
6. MCP 응답은 권한 부여나 법률 판단이 아니라 의사결정 지원임을 매번 명시한다.
7. 현행 원문 대조가 만료되면 단일 경로라도 선택하지 않는다.
8. 같은 최고점 후보가 둘 이상이거나 정확한 제도·단계 키가 없으면 이벤트를 자동 매핑하지 않는다.

## 법령 API와의 역할 구분

- 법제처 API와 `law.go.kr`: 현행 법령·행정규칙 원문의 공식 출처
- Korea100 데이터: 원문을 행위자·단계·문서·기한·분기·인계 관계로 편집한 절차 모델
- 행정절차 MCP: 현재 단계에서 필요한 절차 모델 일부를 에이전트가 안전하게 질의하는 인터페이스

원문 사실과 절차 모델이 충돌하면 공식 원문이 우선하며 MCP는 선택을 중단해야 한다.

## R3 진입 조건

- 해당 기관 현업 담당자가 단계별 업무분장과 실제 수신자를 확인
- 내부 서식명, 필수 입력 필드, 첨부 기준과 보존 위치 확인
- 법정기한과 내부 처리목표를 분리 확인
- 보완·반려·이의·회귀 조건과 종료 조건 확인
- 동일 업무가 기관별로 다른 경우 적용 범위를 구분할 식별자 마련
- 기관별 업무분류·문서유형 코드와 Korea100 단계 ID의 승인된 매핑표

## R4 진입 조건

- 전자결재 이벤트와 절차 노드 간 안정적인 매핑 키
- 문서 ID는 전달하되 본문·개인정보는 최소화하는 이벤트 계약
- 다음 행동 제안의 열람·확인·기각 이력 감사로그
- 쓰기 작업별 최소 권한과 이중 승인 정책
- 잘못된 분기 제안, 법령 개정, 시스템 장애 시 중단·복구 절차

## 현재 한계

- 공개된 505개 전체가 아니라 R2 대표 제도 3개만 대상이다.
- 실제 온나라 이벤트 코드, 기관별 문서서식, 조직·업무분장과 연결되지 않았다.
- 개인정보 탐지는 명백한 형식의 방어선이며 완전한 비식별화 장치가 아니다. 연계 시스템에서 본문·첨부 제거와 별도 DLP 검사가 선행돼야 한다.
- 실행 패킷은 추천 결과일 뿐 전자결재 문서나 공식 처분 기록이 아니다.
