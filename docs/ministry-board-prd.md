# PRD — 부처 상황판 (국정상황판 M1)

> 2026-08-29 v1.0. 기획 원본: `docs/national-situation-board-plan.md`(2판).
> 목적: **국무총리 시점에서 각 부처가 국가 핵심사업에서 맡은 관문을 모니터링**한다.
> 이 문서만 읽고 다음 세션에서 바로 구현 가능한 것을 목표로 한다.

---

## 1. 배경과 문제

korea100 워룸은 사업 축 관제(4사업 135관문)를 제공하지만, 총리의 실제 질문은
부처 축이다 — "해수부가 지금 쥐고 있는 게 뭔가", "행안부가 지연되면 몇 개가 서나",
"공이 어느 부처에서 며칠째 멈춰 있나". 현재 이 질문에 답하려면 사업 지도 4개를
돌아다니며 머리로 접어야 한다.

데이터는 이미 있다(관문마다 `decision`·`lead`·hard 의존·상태). 없는 것은
**부처별 접기 집계와 화면 2장**이다.

## 2. 목표와 성공 기준

| 목표 | 성공 기준 (측정 가능) |
| --- | --- |
| G1. 부처별 "쥐고 있는 것"을 30초 안에 파악 | 홈 진입 → 특정 부처의 착수가능 관문 목록까지 클릭 2회 이내 |
| G2. 지렛대 부처 식별 | 레버리지 기준 상위 부처가 홈에서 정렬·표시됨 |
| G3. 기존 지도와 왕복 | 부처 상세의 모든 관문 행 → 해당 사업 지도 딥링크 동작 |
| G4. 정직성 유지 | §7의 HR 요구 전건 충족(수용 기준에 포함) |
| G5. 운영 무비용 | `npm run generate:warroom-map:all` 한 번에 집계 산출, 수기 갱신 0 |

**비목표(Out of scope, M1):** 인계 교차 뷰(M2) · 신호 다사업화(M2) · 입법 파이프라인
화면(M2) · 부처 공식 보고 연계(M3) · 예산·집행률 · 실시간성 · 로그인/권한.

## 4. 정보 구조와 URL

```
/warroom/ministry/            L0 부처 그리드 (신규, 정적 HTML)
/warroom/ministry/#m=<id>     L1 부처 상세 (같은 페이지, 해시 라우팅 — 지도의 #view= 규약과 동일)
/warroom/map/?p=<pid>         기존 사업 지도 (딥링크 대상, 변경 없음)
/warroom/                     워룸 인덱스 — '부처별 MINISTRY' 링크 추가
```

단일 정적 HTML + 해시 라우팅. 기존 지도(index.html)와 같은 방식(빌드 불필요,
Pages 배포만으로 동작). 부처 id는 로마자 슬러그(`mof`, `molit`, `mnd`, `mois`,
`motie`, `moe`, `mohw`, `msit`, `mafra`, `mss`, `moel`, `fsc`, `mcst`, `kha`,
`assembly`, `pm-office`, `balance-committee`, `kcg`, `mpb`, `unassigned` …).

## 5. 화면 명세

### 5.1 L0 — 부처 그리드

**카드 필드** (부처당 1장):

| 필드 | 원천 | 표기 |
| --- | --- | --- |
| 부처명 · 걸린 사업 수 | 집계 | "해양수산부 · 1개 사업 기준" — **표본 크기 상시 노출(HR-6)** |
| 담당/완료/진행/착수가능 | 집계 | 4카운트. **진행률 막대 금지(HR-3)** |
| 쥐고 있는 것 N건 | frontier∩담당 | 카드에서 가장 큰 활자. 0건이면 회색 "지금 대기 없음" |
| 최대 레버리지 | §6.3 | "⚡ 22 — N33 차등지원 제도화" 형식(관문명 병기) |
| 기다린 지 最장 | frontierSince | "최장 N일째" (M1은 생성 시점부터 누적 시작) |
| 오늘 신호 | signals.json | 광주 관문에만 존재 — 없으면 표시 생략(더미 0 금지) |

**정렬**: 기본 = 쥐고 있는 것 ↓ → 레버리지 ↓. 토글: 관문 수 ↓ / 가나다.
**미특정 카드**: 같은 급으로 그리드 마지막에. "결정주체 확정 필요 61건" — 클릭 시
역할명별 그룹 목록(예: '산업단지 지정권자' 3건 → 어느 사업 어느 관문).
**국회 카드**: 부처가 아님을 표기("의정 협조 대상")하되 같은 그리드에 둔다.

### 5.2 L1 — 부처 상세 (해시 `#m=<id>`)

섹션 순서 고정:

1. **헤더** — 부처명, 4카운트, 걸린 사업 칩(클릭=사업 지도), 최근 집계 시각.
2. **쥐고 있는 것** *(핵심)* — 착수가능∩담당 목록. 행 = `[사업] 관문ID 관문명 ·
   기다린 N일 · 풀리면 ▶M개`. 레버리지 ↓ 정렬. 행 클릭 → `/warroom/map/?p=<pid>`
   새 탭. 0건이면 "지금 이 부처 앞에 대기 중인 관문이 없습니다" 명시(빈 화면 금지).
3. **이 부처를 기다리는 곳** — 이 부처 미완료 관문의 hard 하류 관문 목록.
   행에 하류 관문의 담당 부처 병기(부처 간 협조 지점 노출).
4. **진행 중** — active 관문 목록.
5. **입법 의존** — 이 부처 담당 관문 중 requires에 legislature급 관문이 걸린 것.
6. **신호** — 이 부처 관문에 매핑된 최근 7일 신호(있을 때만, 광주 한정 명시).

### 5.3 워룸 인덱스·지도 연결

- `/warroom/` 내비에 `부처별 MINISTRY` 링크 추가(기존 `관문 지도 MAP` 옆).
- 지도 상세 패널의 결정주체 문자열에 부처 상세 딥링크(`/warroom/ministry/#m=<id>`) —
  선택 구현(P2).

## 6. 데이터 명세

### 6.1 산출물 — `public/warroom/map/ministry-board.json`

`generate-warroom-map-data.mjs --all` 마지막 단계에서 생성(공유 인덱스와 같은 자리).

```jsonc
{
  "generatedAt": "2026-08-29",          // asOfDate 최대값 사용 — Date.now() 금지 아님(노드 스크립트라 가능하나 재현성 위해 소스 기준)
  "projects": [{ "id": "...", "name": "...", "short": "..." }],
  "ministries": [
    {
      "id": "mof", "label": "해양수산부",
      "projects": ["arctic-route"],      // 걸린 사업 (표본 크기)
      "counts": { "own": 13, "completed": 0, "active": 1, "frontier": 5, "planned": 12, "unknown": 0 },
      "maxLeverage": { "gate": "N08", "project": "arctic-route", "name": "…", "blocked": 11 },
      "holding": [                        // 쥐고 있는 것 = frontier ∩ 담당
        { "project": "arctic-route", "gate": "N03", "name": "특별법 시행",
          "since": "2026-08-29", "leverage": 11, "level": "minister" }
      ],
      "awaited": [                        // 이 부처를 기다리는 곳
        { "upGate": "N08", "project": "arctic-route",
          "downGate": "N09", "downName": "…", "downMinistries": ["assembly"] }
      ],
      "active": [ { "project": "…", "gate": "…", "name": "…" } ],
      "legislative": [ { "project": "…", "gate": "…", "blockedByGate": "…" } ]
    }
  ],
  "unassigned": [                         // 미특정 — 역할명별 그룹
    { "role": "산업단지 지정권자", "gates": [ { "project": "…", "gate": "…", "name": "…" } ] }
  ]

```

### 6.2 부처 정규화 — `MINISTRY_CANON` 전면 확장

현재 8부처 → 전 부처·청·위원회로 확장. **규칙(mega-tier에서 학습한 함정 그대로):**

- 부분 문자열은 **구체 토큰만**. "정부"·"부서"·"시장" 같은 일반어 금지
  (재정부서→'정부', 전력시장→'시장' 오매칭 전례).
- 앞선 항목이 우선(예: "기후에너지환경부"를 "환경부"보다 먼저 — 기존 규칙 유지).
- `decision`이 비면 `lead`로 폴백(지도와 동일). 둘 다 역할명이면 **unassigned**로 —
  절대 추정 배정하지 않는다(HR-2).
- 한 관문에 부처가 여럿이면 **모두에게 계상**하고, L0 카드에 공동 담당 표기는 생략하되
  L1 행에 `공동: 국토부` 병기. (합계가 관문 수를 넘는 것은 광주 보드에서 각주로
  처리한 전례를 따름 — 그리드 하단 각주 1줄.)

### 6.3 계산 정의 (구현 기준)

- **frontier(착수가능)**: `status ∉ {completed, active}` 이고 hard 상류가 전부
  `completed`. (지도의 frontier()와 동일 — unknown 포함, planned와 함께 표시하되
  unknown이면 행에 '미확정' 뱃지.)
- **leverage(관문 n)**: hard 엣지만 따라간 하류 도달 집합 크기(자기 제외, 사이클 방지
  방문 체크). 미완료 관문에만 계산.
- **holding**: frontier ∩ (부처가 decision(폴백 lead)에 매칭).
- **awaited**: 부처의 미완료 관문 u에 대해 hard(u→v)인 v 나열. v의 부처도 병기.
- **frontierSince**: 생성 시 기존 `ministry-board.json`을 먼저 읽어, 같은
  (project,gate)가 직전에도 holding이면 기존 since 유지, 처음이면 이번 generatedAt.
  frontier에서 빠지면 소멸. (별도 히스토리 파일 불요 — 자기 자신이 상태 저장소.)
- **legislative**: 관문 requires의 hard 상류 중 level=legislature인 미완료 관문 존재.

### 6.4 신호 매핑

`signals.json`(광주만 존재)의 `byGate`를 부처 담당 관문과 교집합. 다른 사업은
파일이 없으므로 섹션 자체를 렌더하지 않는다(0건 표시 금지 — 수집 안 함과 0건은 다름).

## 7. 정직성 요구사항 (HR — 전건 수용 기준)

| ID | 요구 | 검증 방법 |
| --- | --- | --- |
| HR-1 | 신호는 확정이 아니다 — 신호 섹션에 "언론·브리핑 신호, 확정 아님" 상시 문구 | 화면 검사 |
| HR-2 | 역할명을 부처로 추정 배정하지 않는다 — unassigned 버킷 유지 | 집계 검증: unassigned 수 = 수기 검산 |
| HR-3 | 진행률 막대·백분율 금지 — 4카운트만 | 화면 검사 |
| HR-4 | 모든 수치는 집계 산출 — HTML에 수치 하드코딩 0건 | grep 검사 |
| HR-5 | "업무량·성과" 표현 금지 — "지금 공이 어디 있는가" 프레임 유지 | 문구 리뷰 |
| HR-6 | 표본 크기(걸린 사업 수) 상시 노출 | 화면 검사 |
| HR-7 | 신호 미수집 사업은 0으로 표시하지 않고 섹션 생략 + "수집 범위: 광주" 명시 | 화면 검사 |

## 8. 비기능 요구

- **정적**: 서버·빌드 불필요. fetch 대상은 `ministry-board.json`(+선택 `signals.json`).
  파일 1개 200KB 이하 목표(현 규모에서 여유).
- **성능**: 초기 렌더 1s 이내(정적 JSON 1건 파싱).
- **스타일**: 기존 지도 다크 테마·mono 타이포 재사용(관제실 일관성).
- **접근성**: 카드·행 전부 키보드 포커스 가능, 숫자에 `font-variant-numeric`.
- **해상도**: 1920 기준, 1280까지 그리드 열 수 축소로 대응. 모바일 최적화는 비목표.

## 9. 수용 기준 (Acceptance)

1. `npm run generate:warroom-map:all` 실행 시 `ministry-board.json`이 생성되고,
   부처 수·관문 합계가 이 PRD 작성일 실측(±데이터 변경분)과 일치한다.
2. `/warroom/ministry/` 접속 → 부처 카드 그리드 렌더, 기본 정렬 = 쥐고 있는 것 ↓.
3. 해수부 카드 클릭 → `#m=mof` 상세 → "쥐고 있는 것" 목록의 행 클릭 →
   `/warroom/map/?p=arctic-route` 새 탭이 열린다.
4. 미특정 카드 → 역할명 그룹 목록이 뜬다(61건 기준).
5. HR-1~7 전건 충족.
6. 4개 사업 지도 회귀 없음(기존 Playwright 검증 스크립트 통과).
7. 생성기를 두 번 연속 실행해도 frontierSince가 유지된다(멱등 확인).

## 11. 오픈 이슈

1. **부처 개편 추적** — 산업통상자원부→산업통상부처럼 명칭이 바뀌면 CANON을 고쳐야
   한다. korea100 정부조직 개편 반영 이력(제도 170건 교체 전례)과 같은 절차로 관리.
2. **미특정 61건의 해소 우선순위** — 5극3특 감사(26건 확정) 방식으로 조문 조회하면
   줄일 수 있으나, "지정 경로 미확정"류는 원리상 해소 불가. 해소 가능/원리적 미확정을
   구분 표기할지 M2에서 결정.
3. **공동 담당 이중 계상** — 각주 처리로 시작하되, 그리드 합계를 쓰는 화면이 생기면
   중복 제거 합계를 별도 제공.
4. **frontierSince의 소급** — M1 시작 시점부터 누적이므로 초기엔 "N일째"가 실제보다
   짧다. 화면에 "집계 시작 2026-0X-XX" 각주.
