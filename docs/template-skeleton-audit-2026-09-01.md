# 템플릿 골격 제도 전수 조사 (2026-09-01)

5극3특 R2 승격 작업에서 `regional-balanced-growth-project` 하나가 제네릭 골격인 것을
발견하고, 653개 전체가 어떤지 물었다. 139개였다.

## 무엇을 골격이라고 부르는가

일괄 생성기가 12단 사다리를 만들고 제도명만 접두로 갈아 끼운 것이다. 노드 12개의
이름이 `<제도 설명> + <제네릭 단계>` 꼴로 전부 같다.

```
대상·요건 확인 → 신청·계획 작성 → 접수·등록 → 서류·현장 검토 → 보완자료 제출
→ 관계기관·전문가 심의 → 결정·처분 → 결과 통지·공개 → 이행·서비스·운영
→ 변경·갱신 → 사후점검·기록 → 시정·이의·재신청
```

행위자는 도메인별 4종이 순환하고, 신뢰도는 전부 0.9 단일값이며, 기한은
`개별 법령·공고·통지서에서 확인` 플레이스홀더이고, 연결선 라벨은
`결정 / 시정·불복 / 자료보완 / 재신청 / 조건부·보완` 다섯 개로 고정이다.

판정은 사다리 일치 하나로 한다. 653개를 훑으면 **정확일치 139개, 9단 이상 겹침 0개**로
회색지대가 없다. 문턱을 고민할 필요가 없는 이분이다.

## 왜 기존 검증에 안 걸렸는가

139개 **전부** `article-verified`다. 조문 번호는 실재하는 것을 달고 있기 때문이다.
검증이 본 것은 "이 조문이 법에 있는가"이고, 안 본 것은 "이 절차가 그 조문의 절차인가"다.

구체적인 예. `minimum-wage-determination-notice`(최저임금 심의·결정·고시)는
최저임금위원회 심의와 고용노동부장관 고시가 실제 절차인데, 모델에는
"근로자·사업자가 신청·계획을 작성한다"가 들어 있다. 조문 대조는 통과한다.

## 막고 있던 것과 안 막던 것

**막고 있었다.** `agent-readiness.mjs`의 `TEMPLATE_TEXT`가
`부터.+까지.+대상·요건 확인` 패턴으로 12노드를 전부 잡아 R2를 차단한다.
그래서 **골격 139개 중 R2는 0개**다. 준비도 관문이 제 일을 했다.

**안 막던 것은 가시성이다.** 139개라는 사실을 아무도 몰랐고, 워룸 지도는 이 제도들을
"절차 12개"로 세어 실제 절차가 있는 것처럼 보여 주고 있었다.

## 온톨로지 오염 여부 — 없음

다음 행동을 계산하는 케이스 8건(제도 케이스 7 + 마일스톤 케이스 1)은 골격을 하나도
참조하지 않는다. 계산 가능 마일스톤 5개(N02·N03·N19·N20·N23)의 참조 제도 17종도
전부 골격이 아니다. `mcp/test/skeleton-isolation.test.mjs`가 이를 고정한다.

사업 케이스 4건은 골격을 참조하지만, 그쪽은 그래프 질문(개폐·차단·갈림길)이 본업이고
제도 준비도는 R2로만 세므로 골격은 애초에 계산에 들어오지 않는다.

## 조치

- `web/scripts/detect-template-skeletons.mjs` — 탐지기. `--list`·`--json`·`--gate-r2`.
  `npm run check:skeletons`가 골격이 R2에 오르면 종료코드 1.
- `docs/template-skeletons.json` — 139개 목록(기계용).
- 워룸 지도 — 제도 링크에 `골격` 배지, 관문 상세에 경고 행.
  절차 수가 실제 절차를 뜻하지 않는다는 것을 화면이 말한다.
- 테스트 3건 — 골격의 R2 금지, 실행 케이스 무오염, 계산 가능 마일스톤 무오염.
  탐지가 0을 반환하면 실패한다(사다리 정의가 데이터와 어긋난 것이므로).

## 남은 일

139개 재모델링은 이 조사의 범위가 아니다. 우선순위는 사업에 걸린 것부터다 —
광주 22개가 관문 23개에 걸려 있어 가장 크다. 재모델링 없이 R2로 갈 수 없고,
R2 없이는 그 관문들이 영원히 계산 불가로 남는다.
