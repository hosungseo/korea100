## 1. 계기와 범위

사용자가 Archify(tt-a1i, 레포 하나를 넣으면 클릭해 따라가는 인터랙티브 구조도를 만드는 에이전트 스킬)를 보여주며 "제도가 아니라 법률 및 하위법령 전체를 만들어주는 건 어때?"라고 제안. 브레인스토밍으로 범위를 정했다.

- 단위: 조문 박스 + 법령 레인(법률·시행령·시행규칙 조문 전개, 행정규칙은 제목 박스, 자치법규는 묶음).
- 대상: `legal-source-registry.json`의 법률 278건(실제 고유 ID 277건).
- Archify에서 가져온 것은 렌더러가 아니라 상호작용 문법(호버 연결·클릭 원문·경로 추적·페이지 이동 없음). Archify 자체는 좌표 수작업 JSON IR이라 조문 수백 개 그래프엔 부적합.

## 3. 데이터 파이프라인 (`web/scripts/`)

- 출처: 법제처 DRF `lsStmd`(상하위법 트리) · `lsDelegated`(조문 단위 위임, 법률·시행령·시행규칙 MST 각각) · `eflaw`(현행 조문). OC는 `law-go-kr-oc.mjs`로만 해석, 캐시·산출물·보고서에서 제거하고 검증기가 `OC=` 부재를 기계로 확인.
- 모듈: `lib/law-map-parsers.mjs`(파서) → `lib/law-map-build.mjs`(IR 조립) → `fetch-law-map.mjs`(CLI, 캐시 우선·300ms 간격·백오프) → `validate-law-map.mjs`(참조 무결성·통계 일치·OC 부재·index 동기·분류 파일 점검). `validate:data`에 연결.
- 산출: `web/data/law-map/<lawId>.json`(구조, 압축), `web/public/law-map/<lawId>.text.json`(조문 미리보기 300자, 패널에서 지연 로드), `index.json`, 보고서.
- 실측에서 잡은 함정(스펙 §3에 결정 기록):
  - **lsStmd 실응답은 중첩 구조**(법률>시행령>시행규칙>자치법규). 평면 가정 파서는 실데이터에서 하위법이 전부 빈 배열이었고, 리뷰어가 실응답으로 잡아냈다. 기본정보 직전 태그로 분류하도록 수정.
  - `<위임정보>` 하나에 `<위임구분>`이 여러 개, 머리글 없는 항목(119건)은 링크텍스트로 종류 추론. 같은 법 자기인용이 `인용법령`으로 섞여 옴 → 제외·집계.
  - 라인텍스트는 곡따옴표·`·`, 조문 원문은 직따옴표·`ㆍ` → 정규화 없이는 조례 위임 출발 조문이 제5조의5가 아닌 제5조로 귀속.
  - 법원 관련 법률 23건은 lsStmd가 대법원규칙 등을 시행령 자리에 둠 → 위임선 종류를 도착 레인 층으로 맞춤.
  - 하위 레인 lsDelegated 500은 법률 전체를 버리지 않고 `delegationUnavailable`로 보고, 재시도 1회.

## 4. 화면 — 세 가지 보기 (`web/src/components/LawMap*`)

### 자세히 (#170)
층별 열에 조문 카드. 기본은 선을 숨기고 위임 있는 카드에 색 점·건수. 호버로 그 조문의 선만, 클릭으로 패널(원문·위임 목록·인용 법령·"이 조문을 쓰는 제도"), 경로 모드에서 두 조문 사이 BFS 경로, URL 해시 공유. 제도 페이지 법적 근거에 "법령 지도 →" 링크.

### 구조도 (#171 → #172)
- 1차(#171): 층별 열에 장(章) 블록을 쌓고 열 사이에 묶음 선 → 사용자 "이건 구조도는 아니네"(자리에 뜻이 없는 표). 2차 시도(부모 아래 자식을 옆으로 늘어놓은 트리)는 가로 2.8화면·아래 40% 빈칸이라 폐기.
- 최종(#172): **법률 장 하나 = 기둥**. 기둥 척추선에 시행령 장 → 시행규칙 장 → 행정규칙·조례 묶음이 세로로 매달림. 자리 = 위임을 가장 많이 받는 상위 장(동률은 문서 순서), 고아는 상대 위치에 점선·연결선 없음, 자식 6개 초과는 요약 상자, 다른 기둥으로 건너가는 위임만 색 선(굵기 = 건수). 폭 맞춤 우선·축소 하한 0.85 — 건축법·국가공무원법이 1440px 한 화면. 데이터로 만든 헤드라인 문장, 좌→우 조립 애니메이션(법률당 1회). 순수 모듈 `law-map-tree-layout.mjs`; 리뷰에서 272개 지도 전수 위임선 수지 정확 확인.
- 참고 문법: 사용자가 준 「動くAIスライド」(うちた) — 한 장에 전체 흐름, 클릭하면 옆 패널, 페이지 이동 없음, 1페이지 1동작. 메모리 `reference_moving_slides`.

### 규율 (#173)
법률 조문을 **주체 레인(국민·사업자(공무원 포함)/지자체/중앙/위원회·전문기관/법원·검찰/헌법기관/주체 없음) × 규율 단계(목적·정의→기준·의무→인허가·절차→행정 운영→조직·위원회→감독·시정→벌칙·과태료→보칙, 꼬리 미분류)** 격자에 칩으로. 칸당 5개 + "+N" 제자리 펼침, 칸 발치에 위임 배지, 칩 클릭 → 자세히+패널.

분류는 **규칙 기반 추론 v0.2** (`lib/law-map-classify.mjs`, `classify-law-articles.mjs --all [--sheet --baseline]`): 제목·장·본문 단서표로 단계, 첫 문장 주어로 주체, 공동 주어는 보조 주체, 주어 생략형·사물 주어 규칙. 모든 라벨에 `confidence`·`evidence`·`method`, 근거 없으면 `unknown`. UI는 점선(신뢰도 0.5 미만)·↔(보조 주체)·툴팁 근거·하단 "추론" 문구로 표시. 말뭉치: 미상 12%, 저신뢰 약 30%.

리뷰 1차에서 타 법률 오탐이 드러남 — 부분 문자열 단서(공지⊂인공지능, 공단⊂공공단체, 회의⊂협회의), 주체 명사 누락(처장·교육감·서장·검사), 주어 앞 120자에서 먼저 나온 기관을 주체로 잡는 규칙, 분류 파일 전체(최대 1.2MB)를 페이지에 실어 보냄. 수정 후 같은 20개 조문 정밀도 **단계 19/20→20/20, 주체 14/20→19/20**. 클라이언트엔 법률 조문만 투영.
