# Korea100 온톨로지 PRD

기준일 2026-09-01 · 상태 v0 가동 중 · 정본: 이 문서. 구현 세부는 [README](README.md)·[MCP-MAPPING](MCP-MAPPING.md)

## 한 줄 정의

제도 **맵**(업무구조도)을 **장부**(객체·관계·상태·규칙·액션패킷)로 닫아, 같은 질문에
같은 판단 패키지가 나오게 한다. 공공 액션 층은 시스템 자동 write가 아니라 **사람 승인 패킷**이다.

## 문제

Korea100은 제도 653개의 업무구조도를 갖고 있다. 사람이 읽는 그림으로는 완성이지만,
에이전트가 "지금 이 사건에서 다음에 뭘 해야 하나"를 물으면 세 가지가 없다.

1. **사건이 없다.** 맵은 템플릿이다. "부분공개 통지가 온 내 사건"은 맵 어디에도 없다.
2. **판단 근거가 흩어져 있다.** 어느 조문이 어느 분기를 여는지가 문장 속에 있어
   같은 질문에 다른 답이 나온다.
3. **경계가 없다.** 무엇까지 답해도 되고 무엇부터는 사람 몫인지가 데이터에 없다.

LLM에게 맵을 통째로 주고 묻는 방식은 이 셋을 전부 추정으로 메운다. 온톨로지는
그 추정을 데이터와 규칙으로 바꾸는 작업이다.

## 사용자와 사용 장면

| 사용자 | 장면 | 온톨로지가 주는 것 |
|---|---|---|
| 민원인·당사자 | "부분공개 통지 왔는데 뭐 하면 됨?" | 현재 상태 + 열린 선택지 + 체크리스트 패킷 |
| 담당 공무원 | "의견서 들어왔는데 다음에 뭐 하지?" | 같은 사건, 행정청 쪽 패킷 (주체별 분리) |
| 사업 PMO | "반도체 클러스터에서 뭐부터 할 수 있어?" | 마일스톤 개폐 + 막힌 원인 + 미확정 갈림길 |
| AI 에이전트 (MCP 클라이언트) | 위 질문 전부 | 구조화 응답, `execution_allowed=false` 보장 |

## 제품 원칙

전부 코드로 강제된다. 문서로만 있는 원칙은 없다.

1. **자동 집행 금지.** 모든 패킷은 `auto_execute=false`·`human_confirmation_required=true`.
   위반이면 응답 대신 오류 (`packet-contract.mjs`).
2. **확신 없으면 되묻는다.** 질의가 데모 질문과 충분히 가깝지 않으면 패킷을 만들지 않고
   `case_needs_disambiguation`으로 후보를 되돌린다. 엉뚱한 패킷 > 무응답이 아니라 그 반대다.
3. **구조 층은 파생물이다.** 케이스의 단계·연결선은 제도/오버레이 JSON의 투영이며
   파생기(`derive-*.mjs`)가 만든다. 손으로 옮겨 적으면 옮겨 적는 순간부터 어긋난다.
   사람은 사건 고유 층(Case·State·Rule·ActionPacket)만 쓴다.
4. **주장은 검사된다.** 케이스가 "이 제도/마일스톤을 채운다"고 선언하면 매 질의마다
   원본과 대조하고(`case-link.mjs`), 어긋나면 `drifted` + 다음 행동 차단.
5. **없는 것은 없다고 말한다.** 법령에 없는 기한·절차는 지어내지 않는다. 법의 침묵은
   `unverified`·`not_a_statutory_step`으로 데이터에 남는다 (예: 예타의 지자체 건의 P16).
6. **등급이 곧 답변 범위다.** 참조 제도가 R2가 아니면 그 사유가 패킷 `risks`로 흘러나가고
   다음 행동 계산이 막힌다. 사업은 가장 준비 안 된 제도만큼만 계산된다.

## 아키텍처 — 세 층

```
[제도 데이터 층]  web/data/institutions/*.json (653) + agent_readiness (R2 17종)
       │  파생 (derive-case / derive-project-case / derive-milestone-case)
[온톨로지 층]     ontology/samples/*.case.json (9) — Entity·Relation·State·Rule·ActionPacket
       │  질의·대조·계약
[MCP 층]         mcp/ — 읽기 전용 stdio 서버, 도구 13종, 테스트 87건
```

### 케이스 종류 (case_kind)

| 종류 | 단위 | 답하는 질문 | 단계 ID | 현재 |
|---|---|---|---|---|
| `institution` | 제도 하나, 사건 하나 | 그 제도의 어느 단계인가 | `step:Pxx` | 7건 |
| `project` | 사업 하나, 제도 여럿 | 어느 마일스톤이 열렸나 | `milestone:Nxx` | 1건 (광주 반도체) |
| `milestone` | 마일스톤 + 제도 여럿 | 제도들 중 어느 **조합**을 밟을지 | `step:<slug>:<Pxx>` | 1건 (N23) |

층은 서로를 검사한다. 제도 케이스는 `project_context`로 자기가 채우는 마일스톤을
선언하고, 그 마일스톤이 실제로 그 제도를 참조하는지 대조된다. 한 마일스톤에 케이스
둘이 붙을 수 있다(N03: 반도체클러스터 지정 + 특화단지 — 법이 중복 지정을 허용).

### 준비도(R2)와 두 축

마일스톤이 "다음 행동 계산 가능"이 되려면 두 축이 함께 열려야 한다.

- **제도 준비도 축** — 참조 제도 전부 R2. 조문 전문 대조·전이 수동 대조·법제처
  현행 시행본 대조(`target=eflaw`, 시행일 지정)를 통과해야 하고, 근거가 약한 단계는
  참고용으로 격리하되 격리 후 경로가 끊기면 R2 불가.
- **사업 파라미터 축** — 사업이 정해야 열린다 (`gridPath` 등). `get_pending_decisions`가
  미확정 파라미터와 그것이 여닫는 마일스톤을 모아 준다. **무엇을 고를지는 말하지 않는다.**

### MCP 도구 13종

R2 절차 6종(검색·지도·요건·다음행동·이벤트매핑·패킷) + 온톨로지 7종
(케이스 로드·상태·질의·대조, 프로젝트 상태·차단원인·미확정 갈림길).
R2 경로와 온톨로지 경로의 패킷은 같은 ActionPacket 계약을 통과한다.

## 로드맵

**M1 — 케이스 운영성 (다음)**
- 상태 갱신 경로: 지금 케이스 상태는 스냅샷이다. 사건이 진행되면 사람이 State를
  갱신하는 절차(또는 `resolve_work_event` 연계)를 정의한다.
- 오버레이 용수 파라미터화 제안 반영 여부 결정 (`waterSupplyEntity` 등 3종 —
  전력 `gridPath`와의 비대칭 해소, 사업 데이터 소유자 승인 필요).
- N24·N50 등 하류 마일스톤 케이스 확장.

**M2 — 다른 사업·제도로 복제**
- 메가프로젝트 3종(5극3특·북극항로·대구경북신공항)에 project 케이스 파생.
- 환평·예타 등 범용 제도의 일반 사건 케이스(1·2호 계열) 확충.
- 케이스 저작 가이드 문서화 — 사건 고유 층 작성 규칙을 레시피로.

**M3 — 실행 게이트웨이 전 단계 (기존 MCP 로드맵과 합류)**
- R3: 현업이 실제 업무분장·서식·시스템 필드를 확인.
- 이벤트 어댑터: 기관 코드 → 제도 slug·단계 매핑.
- 실행은 별도 게이트웨이로 분리, MCP는 영구히 읽기 전용.

## 비목표

- **법률 해석·자문이 아니다.** 조문 번호 존재와 절차 구조를 보증할 뿐, 개별 사건
  적용 타당성은 범위 밖이다 (모든 응답에 면책 유지).
- **자동 결재·접수·발송이 아니다.** 영구 원칙. 실행이 필요해지면 별도 게이트웨이.
- **653종 전량 온톨로지화가 아니다.** 수요가 있는 축(사업·빈발 민원)부터 소수 정예.
- **추론 엔진이 아니다.** 규칙은 선언이고 계산은 결정적이다. 그래프에 없는 답은
  만들지 않는다.

## 성공 지표

- 같은 질문 → 같은 패킷 (결정성): 데모 질의 전건 테스트로 상시 검증
- 케이스↔원본 어긋남 0 유지 (`aligned` 전건, CI에서 확인)
- 패킷 계약 위반 0 (위반은 응답이 아니라 오류)
- 검증 과정에서 발견되는 원 데이터 실오류 수 — 이 수가 유지되는 것 자체가
  온톨로지 층이 검사 기능을 하고 있다는 증거다
