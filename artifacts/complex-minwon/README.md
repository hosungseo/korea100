## 문법
- 색: 초록 규정(조문 항·호·목까지 표기, 법제처 현행본 기계 대조) / 파랑 추론(규정에 없는 실무). 표시판: 노랑 통합 · 보라 자동화 · 주황 축소 · 빨강 갈음·폐지 검토.
- 가로축 = 기관, 세로축 = 관문. 모든 칸에 수행 기관 딱지(🏛/👤). 개선 카드의 "→ 기관 — 조문"은 **수행 기관이 아니라 조문 소관**이다.
- 자동화 후보 선별 기준: 법이 '어떻게'까지(날짜·계산식·서식) 정한 구간.

## 배선 (선이 겹치지 않는 이유)
선은 카드가 없는 곳만 지난다 — ①관문 행 하단의 빈 띠(거터 52px) ②카드 좌우 여백·열 사이 통로 ③같은 칸 카드 사이 틈.
한 선마다 후보 경로를 수천 개 만들어 **카드 관통 → 기존 선과 나란히 겹침 → 길이** 순으로 채점해 가장 좋은 것을 고르고, 고른 경로의 모든 구간을 등록해 다음 선이 그 자리를 피한다. 카드에 붙는 선이 여럿이면 변을 나눠 쓴다(같은 점에서 겹쳐 나가지 않게).

## 도구 (`_lib/`)
- `fetch-laws.py` — 법제처 DRF 현행본(eflaw + efYd) 스냅샷, `admrul`로 고시·훈령도 같은 스키마로.
- `verify-basis.mjs` — 사례 `case-data.mjs`의 모든 인용을 `laws/*.json`과 항·호·목 단위 대조, 조작 인용 음성 대조군 포함.
- `gen.mjs` — HTML 2장 + PNG @2x (playwright 전역 설치 필요).
- `check-overlap.mjs` — 렌더된 판을 열어 **카드 관통 · 테두리 근접 · 선 겹침**을 센다. 관통·겹침이 0이 아니면 종료코드 1.
  `node _lib/check-overlap.mjs */*-full.html */*-improve.html` → 1–3호 네 장 관통 0 · 겹침 0. 4호는 관통 0, 선 겹침 잔여(`04-deemed-bundle/README.md`).
- `compare/` — 절차 비교대조 엔진(추출→대조→판정→카드). `04-deemed-bundle/README.md` 참조.

새 호: 폴더 만들고 `case-data.mjs`(meta·lanes·gates·nodes·edges·improvements·groups·orgOrder) 작성 → `laws/` 채우기 → 두 줄짜리 `gen.mjs`·`verify-basis.mjs` 복사 → `node verify-basis.mjs && node gen.mjs --png`.
