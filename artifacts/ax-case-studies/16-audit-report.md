# 감사 보고 (2026-08-22)

사례 체계도 131건에 대해 3중 감사를 실시하고 결과를 반영했다.

## 1. 구조 감사 (자동, `audit-cases.mjs`)

20종 규칙을 전 파일에 적용. 노드 형식·kind 유효성·게이트/레인 범위·엣지 참조 무결성·
대체(replaced) 노드의 AS-IS 실재 여부·`A0n로 대체` 태그가 가리키는 auto 노드 존재·
statute 노드의 조문번호 유무·**headline 숫자와 실제 노드 집계 일치** 등.

- 초기 실행에서 헤드라인 집계 불일치 2건 적발 → 수정
- 최종: **128건 ERROR 0 / WARN 0**

## 2. 법령 인용 감사 (`verify-law.mjs`) — 대기 중

인용된 모든 (법령명, 조문)을 법제처 국가법령정보 공동활용 API(DRF)로 전수 대조하는 감사기.
**법제처 사이트 전체가 시스템 점검 중**이라 실행하지 못했다(메인 페이지까지 "시스템 점검" 반환,
공공데이터포털 미러는 서비스키 필요). 감사기는 점검 페이지를 "법령 미검출"로 오판하지 않도록
구분하고, `--wait` 옵션으로 복구 시 자동 실행되도록 대기 상태로 걸어 두었다.

그래서 작성 단계에서 **"확신 없으면 조문을 지어내지 말고 파랑(추론)으로 두라"**는 원칙을 적용했고,
그 결과 추론 비율이 82.8%로 높다. 이는 정직한 상태이지만 규정/실무 대비는 약해졌으므로,
API 복구 후 ① 인용 전수 검증 ② 근거 확실한 단계의 초록 승격 ③ 집계 재계산이 필요하다.
전 사례의 basisNote 도입부를 `근거(인용 법령 — 법제처 원문 대조 대기)`로 통일해 검증 상태를 명시했다.

### 소멸(removed) 판정 재검토 — 중요
근거 없는 소멸 2건을 강등한 결과, **소멸은 3건만 남았다**(광주 당직제 폐지 2, 국과수 대조파일 방식 1).
모두 **사람이 제도·방식을 실제로 폐지한 경우**다. "AI가 절차를 없애는 것이 아니라, 제도를 폐지할 때만
절차가 사라진다"는 명제가 감사를 거치며 오히려 선명해졌다.

|---|---|---|

### 감사기 수정
- `resultMsg=success`인 유효 XML을 받았을 때만 부정 결과를 캐시(일시 장애가 영구 오탐으로 굳는 경로 차단)
- 법령명 비교 시 가운뎃점 표기(`·` U+00B7 / `ㆍ` U+318D / `･`)와 공백 차이를 정규화
