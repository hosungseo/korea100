# 삼성 L7 조사와 HTA — 우리 137건 데이터에서 나오는 시사점

소재: ① 삼성전자 DX부문 'L7(업무 자동화 여부 조사)' — L6(업무)를 L7(Step)로 쪼개 전 직원이
3일 안에 자기 업무를 동작 단위로 작성. 사내 반발("수백 개 자잘한 업무를 왜 하나하나 쓰게 하나")
② 학술 프레임 HTA(Hierarchical Task Analysis) / Task Decomposition / BPM(Process→Activity→Task)

---

## 1. 같은 층위를 겨냥했다 — 우리 체계도의 노드가 곧 L7이다

삼성의 L6→L7은 HTA의 Task→Operation이고, 우리 체계도의 노드가 정확히 그 층위다.

| 프레임 | 층위 | 우리 체계도 |
|---|---|---|
| BPM | Process | 사례 1건(예: 출장 여비 정산) |
| BPM | Activity | **게이트**(G0 신청 → G1 확인 → …) |
| BPM/HTA | Task | **노드**(P08 카드 결제·증거서류 확보) |
| HTA | Operation/Action | 우리는 **의도적으로 내려가지 않음**(→ 4장) |
| — | Actor | **레인** — HTA에 약한 축을 스윔레인으로 보완 |

용어를 잡는다면 `Process → Activity → Task → (Task Step) → Action`이 타당하고, 우리 작업은
**"Task 층까지의 HTA + 행위자 간 인계를 그리는 스윔레인"**의 결합이라고 쓰면 정확하다.
HTA는 한 사람의 과업 계층에 강하지만 **여러 행위자 사이의 인계**를 잘 못 그린다. 행정업무는
인계가 본질이므로(접수자→담당자→결재자→통지) 이 결합이 방법론적 차별점이 된다.

## 2. 결정적 차이 — 삼성은 사람에게 물었고, 우리는 법령에서 뽑았다

| | 삼성 L7 | 우리 137건 |
|---|---|---|
| 정보 출처 | **당사자 자기보고**(3일 내 수백 개) | **법령 원문 + 실무 추론** |
| 당사자 부담 | 백지에서 전부 작성 | "이 그림이 맞습니까" 교정만 |
| 유인 구조 | 자기 일을 자동화 대상으로 신고 → **왜곡** | 판정은 문서가, 당사자는 사실 확인만 |
| 품질 | 실제 경험이나 편차 큼 | 초록은 전수 검증, 파랑은 추정(교정 필요) |

삼성 방식의 근본 문제는 품질이 아니라 **유인**이다. 사람은 자기 일이 없어지게 만드는 자료를
성실히 쓰지 않는다. 사내 반발("짓거리를 왜 합니까")은 게으름이 아니라 합리적 반응이다.

**공공은 여기서 민간보다 유리하다.** 법령·조례·훈령이 공개돼 있어 업무의 뼈대를 사람에게 묻지
않고 뽑을 수 있다. 삼성에는 그런 공개 골격이 없어 전 직원에게 물을 수밖에 없었다.
우리가 137건 1,678단계를 분해하는 데 든 현업 공무원의 시간은 **0시간**이다.

## 3. 자동화 가능성은 '동작'이 아니라 '규정 유무'로 갈린다 — 이게 핵심 발견이다

삼성은 각자에게 "꼭 사람이 해야 하는지"를 판단시켰다. 주관적이고, 사람마다 기준이 다르고,
유인이 왜곡된다. 우리 데이터는 **문서만으로 사전 판정할 수 있는 강한 변수**를 찾아냈다.

- 대체 573건 중 **95.6%가 규정 밖(파랑) 단계**에서 나왔다. 규정 단계는 4.3%만 넘어갔다.
- 예외 25건도 규칙적이다 — **법이 이행 방법(계산식·서식·기록)까지 특정한 경우**
  (여비 규정 별표 운임표, 수당 산식, 활동일지 기록 의무 등).

정리하면 **자동화 가능성 판정에 사람의 주관이 필요 없는 구간이 상당하다.**

> 법이 **결과만** 정했으면 → 방법은 실무가 만든 것 → **자동화 1순위**
> 법이 **방법까지** 정했으면 → 정답이 하나 → **역시 자동화 대상**(계산·기록·판정)
> 법이 **사람의 의사표시로 규정**했으면(신청·결재·통지·이의) → **사람이 남는다**

즉 전 직원에게 묻기 전에 **법령만으로 상당 부분을 먼저 판정**할 수 있다. 사람에게 물어야 하는
것은 "이 파란 칸이 실제로 우리 기관에서도 이렇게 돌아갑니까" 하나로 줄어든다.

## 4. HTA의 고질적 난제 — 어디까지 쪼갤 것인가(stopping rule)

삼성은 "냄비에 물 500ml 붓기 / 가스불 켜기"처럼 물리적 동작까지 내려가게 했다. 그래서 수백 개가
되고 반발이 생겼다. HTA 문헌의 고전적 정지 규칙은 P×C(실패확률×비용)인데 실무에서 적용이 어렵다.

**우리 데이터가 제시하는 실용적 정지 규칙은 이것이다.**

> **규정이 방법을 정하지 않은 지점까지만 내려간다.**

그 아래(엑셀 열기 → 셀 선택 → 숫자 입력)는 도구가 알아서 하는 층위이고, AX 판단에 필요한 정보는
이미 그 위에서 다 나온다. 실제로 우리는 **사례당 평균 12.2단계**로 충분했다. 라면을 5단계로
쪼갤 필요가 없다 — 필요한 것은 "물 붓기"가 아니라 **"규정이 결과만 정한 구간이 어디인가"**다.

## 5. 삼성 방식이 갖고 우리가 못 가진 것 — 빈도(frequency)

공정하게 말하면 자기보고에는 우리에게 없는 정보가 있다. 삼성은 **"일/주/월 단위로 얼마나 자주
하는지"**를 함께 받는다. 절감 효과 추정에는 `단계 수 × 빈도 × 소요시간`이 필요한데 우리 데이터에는
빈도 축이 없다.

→ **개선 제안**: 체계도 노드에 `freq`(일/주/월/연/건별) 속성을 추가한다. 이건 담당자에게 물어야
하지만, 백지 작성이 아니라 **이미 그려진 12개 노드에 빈도만 표시**하는 것이라 부담이 1/10이다.
그러면 "이 업무 AX 시 연 N시간"이 산출되고, 안양시(연 450시간)·경기도(연 1,382→192시간)처럼
정량 근거를 갖춘 사례와 같은 층위로 비교할 수 있다.

## 6. 루프 — HTA에도 BPM에도 약한 축

HTA는 plan(순서·조건)을 다루지만 **되돌아가는 고리의 존속**은 다루지 않는다. 우리는 160개 루프의
운명을 추적해 이런 결과를 얻었다.

- 그대로 유지 32.5% / **재정착 47.5%**(그중 73개가 AI 레인으로) / 소멸 20%
- 법정 절차에 착지하는 루프는 60.5%가 그대로, 규정 밖 실무 착지는 22.2%만 그대로
- **이의·불복 100% 유지 / 재탐색·재조회 78.9%가 기계로 재정착**

"AI는 고리를 없애지 못하고 되돌아갈 상대를 사람에서 기계로 바꾼다"는 명제는 기존 프레임에
없던 것이라 **연구 기여 지점**이 될 수 있다.

## 정책 제언 — 공공은 삼성처럼 하면 안 된다

전 직원 자기보고 방식은 공공에서 더 위험하다. 수십만 명 × 수백 개 업무이고, 반발이 크고,
품질 편차가 크며, 무엇보다 **자기 일을 없앨 자료를 스스로 쓰게 하는 유인 구조**다.

**대안은 2단계다.**

1. **법령 기반 사전 분해** — 공개된 법령·조례로 업무의 뼈대(초록)를 그리고, 규정이 방법을 정하지
   않은 구간(파랑)을 추정해 채운다. 현업 시간 0.
2. **당사자 교정** — 담당자에게 "이 그림이 맞습니까 / 파란 칸이 실제로 이렇습니까 / 얼마나 자주
   합니까"만 묻는다. 백지가 아니라 초안이므로 응답 부담이 급감한다.

프레이밍도 **"업무 조사"가 아니라 "업무 지도 교정"**으로 바꿔야 한다. 전자는 감시로 읽히고
후자는 협업으로 읽힌다. 삼성 사례가 보여준 반발은 방법론의 문제가 아니라 **묻는 방식의 문제**다.

이 2단계는 이미 137건으로 실증됐다. 워킹그룹 세미나에서 발표자에게 AS-IS 체계도를 미리 보내고
"틀린 곳을 고쳐 주십시오"로 시작하자는 제안이 곧 2단계의 실행이다.

## 학술 용어 정리(연구계획서용)

> **업무 프로세스 계층분석(Process/Task Hierarchical Analysis)**
> `Process → Activity → Task → Task Step → Action`
> 이 중 **Task 층까지 HTA 방식으로 분해**하고, 행위자 간 인계는 **스윔레인**으로 병기한다.
> 정지 규칙은 **"규정이 방법을 정하지 않은 지점"**으로 둔다.
> 각 Task에 **법적 근거 유무**를 표시해 자동화 가능성을 1차 판정하고,
> 빈도(freq)를 덧붙여 절감 효과를 추정한다.
> `업무 계층분석 → 법적 근거 판정 → 당사자 교정 → Task별 자동화 가능성 평가 → AI/RPA 적용`

**시사점**: ①번 PMAx의 문제의식은 우리가 이미 겪은 것과 같다 — LLM에게 직접 판정을 맡기면
환각이 난다. 우리가 `verify-law.mjs`로 법제처 원문 대조를 붙이고 음성 대조군까지 돌린 것이
정확히 이 대응이다. ②번은 **"로그만으로는 부족하니 전문가 서술을 넣자"**는 방향인데,
우리는 한 걸음 더 가서 **법령 텍스트를 규범 골격으로 썼다**. ⑤번 ProLiFIC은 법령 텍스트를
LLM으로 구조화한다는 점에서 우리와 가장 가깝지만, **입법 과정 자체**를 다룰 뿐
**법령이 규율하는 집행 업무**를 다루지 않는다 — 우리 자리가 비어 있다.

## B. 태스크 마이닝의 진화 — 화면 로그에서 과업 모델로

| 논문 | 번호·시기 | 내용 |
|---|---|---|
| ★ **Inducing Task Models from Computer-Use Traces** | 2608.20319 · 2026-08 | 화면 캡처·마우스/키보드 기록에서 **계층적 목표 모델을 유도(TMI)**. 기존 기법이 "단일 워크플로 가정 + 단계 요약"에 그쳤다면, 이 연구는 **뒤섞인 다중 과업을 분리해 구조화된 과업 모델**을 만든다 |
| **AutoRPA: GUI Automation through LLM-Driven Code Synthesis from Interactions** | 2605.21082 · 2026-05 | 상호작용 기록에서 자동화 코드 합성 |
| **Log2Plan: Adaptive GUI Automation with Task Mining** | 2509.22137 · 2025-09 | 태스크 마이닝을 GUI 자동화에 접목 |
| ★ **Are LLM Agents the New RPA?** | 2509.04198 · 2025-09 | UiPath(RPA) vs Claude Computer Use 통제 실험. **반복·안정 환경에서는 RPA가 속도·신뢰성 우위**, 에이전트는 유연성 우위 |

**시사점**: "Inducing Task Models"는 **HTA의 목표 계층을 사람에게 묻지 않고 화면 로그에서 유도**한다 —
HTA 자동화의 최전선이다. 다만 **화면에 기록이 남아야 한다.** 우리 파란 칸 중 상당수(선임에게
물어보기, 구전 인수인계, 종이 매뉴얼 뒤지기, 현장 확인)는 화면 밖에서 벌어지므로 여전히 안 잡힌다.
④번은 실무적으로 중요한 균형추다 — **모든 것을 에이전트로 바꾸는 게 답이 아니다.**

## C. 과업 단위 AI 노출도 — 경제학·노동연구 쪽 접근

| 논문 | 번호·시기 | 내용 |

| **Global Automation Atlas** | 2605.17086 · 2026-05 | 자동화 지도 |
| **From Exposure to Adoption: Generative AI in European Workplaces** | 2604.18849 · 2026-04 | 노출도와 실제 도입의 간극 |

**시사점**: 이 계열이 삼성 L7과 같은 발상을 **학술적으로 대규모 수행**한 것이다. 다만 결정적 차이가
있다 — 이들은 **직업 분류 체계(O*NET)를 분해**하지 **특정 조직의 실제 업무**를 분해하지 않는다.
그래서 "이 직업이 얼마나 노출됐나"는 답하지만 **"우리 기관의 이 업무를 어디부터 손대야 하나"**는
답하지 못한다. 우리 137건은 후자다.

## 종합 — 우리 작업의 좌표

최신 연구는 세 갈래로 갈라져 있고, **세 갈래가 공통으로 놓치는 자리에 우리가 있다.**

| 갈래 | 정보원 | 강점 | 놓치는 것 |
|---|---|---|---|
| 프로세스 마이닝 × LLM | 이벤트 로그 | 실제 실행 데이터 | **로그에 안 남는 일**(수기 검색·구전·현장) |
| 태스크 마이닝 / 과업모델 유도 | 화면·입력 기록 | 동작 수준 정밀 | **화면 밖의 일**, 수집 부담·프라이버시 |
| 과업 노출도(경제학) | 직업 분류(O*NET) | 대규모·비교가능 | **특정 조직의 실제 업무가 아님** |
| **우리** | **공개 법령 + LLM 추론 + 당사자 교정** | 로그·화면 없이 **규정 밖 실무까지** 추정, 현업 시간 0 | 파랑은 추정이라 검증 필요 |

특히 두 편이 우리 방법의 정당성을 뒷받침한다.
- **Integrating Domain Knowledge(2510.07161)**: 로그만으로는 부족하니 자연어 지식을 넣으라 —
  우리는 그 자연어 지식을 **개인의 서술이 아니라 법령**에서 가져왔다(더 검증 가능하다).
- **PMAx(2603.15351)**: LLM에게 판정을 맡기면 환각이 난다 —
  우리는 법제처 API 전수 대조 + 음성 대조군으로 이미 대응했다.

**연구 포지셔닝 문장(초안)**
> 프로세스 마이닝은 이벤트 로그를, 태스크 마이닝은 화면 기록을 요구한다. 그러나 행정업무에서
> 자동화 여지가 가장 큰 구간(수기 검색·대조·구전 인수인계)은 어느 쪽에도 기록되지 않는다.
> 본 연구는 **공개 법령을 규범 골격(Work-as-Imagined)으로 삼고 LLM으로 실무(Work-as-Done)를
> 추정한 뒤 당사자가 교정하는 2단계 방법**으로, 로그 없이 규범–실무 간극을 도출하고
> 그 간극에서 자동화 대상을 식별한다. 137개 행정업무 사례에 적용해 업무 단계 1,678개를 분해했다.
